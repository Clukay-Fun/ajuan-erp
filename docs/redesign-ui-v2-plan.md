## 给执行 agent 的说明

本计划一次性交给执行者连续执行，共 11 个阶段，必须按顺序完成。每个阶段完成并通过验收后，单独提交一次 commit。

1. 动手前先通读全文。在 `redesign/ui-v2` 分支上工作，不要直接改 `main`。
2. 每个阶段都包含三部分：目标、任务清单、验收标准。只有验收全部通过，才能进入下一阶段。commit message 格式为 `redesign(phase-N): <一句话>`。
3. 新建 `docs/redesign-notes.md` 作为工作日志，记录三类内容：现状盘点、计划外的决定、与本计划的偏差。
4. 遇到计划没写到的细节，默认采用「最小改动、保持现有行为」的做法，并记进日志，不要停下。
5. 遇到以下情况必须停下来问用户：
   - 需要修改数据库表结构或做数据迁移
   - 需要修改任何写入逻辑（建单、生效、作废、调整、导入、备份恢复、清空）
   - 要删除用户可见的功能
   - 要引入计划外的运行时依赖
6. 视觉以本计划的 token 和布局描述为准。如果后续 `docs/redesign/mockups/` 中出现设计稿，以设计稿为准。
7. 计划里的文件路径以 `src/renderer/src/` 为根。实际目录结构如有不同，以阶段 0 的盘点结果为准，并在日志中写明对应关系。

## 目标与已锁定决策

本次重构要把阿卷 ERP 改成一个人用起来顺手的工作台，有四个目标：

- 首页一眼看到今天该处理什么
- 详情与编辑不再弹窗套弹窗
- 开单几秒钟能完成
- 定制把「配置」和「生产」分开

下表中的决策已经定死，执行时不要另做选择。

| 领域 | 决策 |
| --- | --- |
| 使用者 | 店主一个人用，商品不超过 10 个。不做分页，不做权限，界面偏紧凑 |
| 品牌色 | 保留墨绿并降低饱和度。只用于主按钮、导航选中态、焦点环和链接 |
| 数据颜色 | 一律不用绿色表达数据。入库为蓝，出库为琥珀，调整为紫，期初为灰蓝，作废为灰色加删除线。正负值用 +/− 号和 ▲▼ 箭头表示，文字保持中性色。红色只用于错误、告急和负毛利 |
| 深色主题 | 品牌色也统一为墨绿（提亮版）。紫罗兰不再作为品牌色，因为它会与「调整」的紫色撞色 |
| 组件库 | 新增 `@base-ui/react`，这是唯一新增的 UI 运行时依赖。样式继续使用 CSS Modules 和 CSS 变量 |
| 命令面板 | 用 Base UI 的 Dialog 加自写列表实现，不引入 cmdk |
| 图表 | 继续手绘 SVG，在现有 `TrendChart.tsx` 基础上重写 |
| 详情与编辑容器 | 统一使用右侧抽屉，同一时刻最多打开一个抽屉。模态框只用于不可逆操作的确认 |
| 数据层 | 只允许新增只读查询，通过 preload 暴露。不改表结构，不改写入逻辑 |
| 定制 | 拆成「生产」和「模板」两个视图，模板的新建和编辑走分步向导 |
| 范围 | 本期覆盖全部模块：概览、商品、单据、定制、设置，以及全局外壳 |
| 概览默认时间 | 近 30 天。如果近 30 天内没有单据，自动切换到最近一笔单据所在的 30 天 |
| 快捷键 | ⌘/Ctrl 组合键，不占用 ⌃Space（中文输入法切换键） |

## 约束与禁区

这是一次界面重构：业务数据的读写行为必须和重构前完全一致。

### 禁止

- 修改数据库表结构，或新增迁移
- 修改任何写入逻辑的语义，包括单号生成、移动平均成本、生效、作废冲回、调整、CSV 导入、备份恢复、示例数据、清空
- 关闭 `contextIsolation` 或 `sandbox`、开启 `nodeIntegration`，或让 renderer 直接访问 Node
- 引入 Tailwind、CSS-in-JS，或 Ant Design、MUI 之类自带样式的成套组件库
- 删除或跳过现有测试（被删除组件对应的测试除外，且必须写出替代测试）
- 使用 ⌃Space 作为快捷键

### 允许

- 新增运行时依赖 `@base-ui/react`（锁定确切版本，并确认兼容 React 19.3）
- 新增开发依赖 `@playwright/test`，仅用于截图和端到端冒烟测试
- 新增只读 IPC 与 preload API，每个都要有 zod 返回值校验和单元测试，清单见阶段 4
- 新增一个与业务数据无关的窗口 IPC：在 Windows 上切换主题时同步标题栏 overlay 的颜色
- 在 renderer 的 `localStorage` 里保存纯界面偏好，如侧栏折叠状态、上次使用的渠道、上次使用的定制模板。读写都要包在 `try/catch` 里

### 必须保留的功能

位置可以挪，但不能消失。

| 功能 | 新位置 |
| --- | --- |
| 导入 CSV、下载模板 | 「开单」菜单、命令面板、单据页的「更多」菜单、设置 › 数据 |
| 导出全部流水 | 商品页的「更多」菜单、命令面板 |
| 逐日明细导出 | 概览趋势卡的「明细」视图 |
| 单个商品流水导出 | 商品抽屉 › 库存流水 |
| 新建、编辑、停用商品 | 商品页、商品抽屉 |
| 库存调整（盘亏、盘盈） | 商品抽屉内嵌表单；「开单」菜单 |
| 入库单、出库单、草稿、生效、作废、删除草稿、图片附件 | 单据页、单据抽屉、开单抽屉 |
| 定制全部能力：模板、图层映射、槽位、素材导入、抠白底、生成、导出格式、任务、同步结果、打开 PS | 定制 › 生产 / 模板 |
| Photoshop 设置：插件状态、安装说明、准备 UXP 插件、桥接目录、导出目录 | 设置 › Photoshop 连接 |
| 主题、渠道管理、备份恢复、示例数据、清空、更新检查、自动检查、应用信息 | 设置对应分组 |

### 硬性指标

- 在 960×640 的最小窗口下，每个页面都可用，且没有横向滚动条
- 浅色和深色主题下，正文文字对比度 ≥ 4.5:1，组件边界对比度 ≥ 3:1
- 所有图标按钮都有 `aria-label` 和 Tooltip，所有可交互元素都有可见的焦点环

### 字体与尺寸

- 字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei", sans-serif`
- 单号使用等宽字体：`"SF Mono", Menlo, Consolas, monospace`

## 阶段 4：只读数据接口

本阶段新增 6 个只读查询，主进程里只允许执行 `SELECT`。如果现有 API 已经能提供同样的数据，优先复用现有 API，并在日志中注明。

通用要求：

- 每个接口都按 main 查询函数 → IPC handler → preload 暴露的链路实现
- 返回值用 zod schema 校验，schema 放在 shared 目录，main 和 renderer 共用
- 每个接口都要有 vitest 单元测试，用内存数据库或测试夹具，并覆盖示例数据

统计口径（所有接口都遵守）：

- 只统计「已生效」的单据。草稿不计入；已作废的单据和它的作废冲回都不计入
- 出库金额 = 出库数量 × 售价
- 出库成本 = 出库时的成本快照
- 毛利 = 出库金额 − 出库成本
- 调整和期初不计入销售与毛利
- 日期按本地时区的自然日计算

| 接口 | 参数 | 返回 | 用途 |
| --- | --- | --- | --- |
| `stats.getSummary` | `{ from, to }` | 本期和上一个等长周期各一份：出库金额、出库成本、毛利、毛利率、出库件数、出库单数、入库件数、入库金额 | 概览 KPI |
| `stats.getDailySeries` | `{ from, to, productId? }` | 每天一行：入库件数、入库金额、出库件数、出库金额、毛利。没有单据的日期也要返回 0 | 趋势图、逐日明细、导出 |
| `stats.getLatestActivityDate` | 无 | 最近一张已生效单据的日期，没有则返回 null | 智能选择默认时间范围 |
| `stats.getProductHealth` | `{ windowDays = 30 }` | 每个启用中的商品一行：库存、平均成本、库存成本、预警值、窗口内出库件数、窗口内出库单数、可售天数、健康状态 | 概览库存卡、商品列表、待处理 |
| `documents.getPendingSummary` | 无 | 草稿列表（单号、类型、日期、数量、金额）和草稿总数 | 待处理、侧栏角标、单据页签计数 |
| `products.getLastPrices` | `{ productIds }` | 每个商品返回最近一次已生效入库的进价、最近一次已生效出库的售价，没有则为 null | 开单时自动带出单价 |

### 可售天数的算法

日均出库 = 窗口内出库件数 / `windowDays`

可售天数 = `floor(库存 / 日均出库)`

- 窗口内出库单数少于 3，或日均出库为 0 时，可售天数返回 null，界面显示「—」，并提示「样本不足」
- 库存小于等于 0 时，可售天数为 0

健康状态判定，按以下顺序取第一个命中的：

1. `out`：库存 ≤ 0
2. `critical`：可售天数不为 null，且小于 7
3. `low`：设置了预警值，且库存 ≤ 预警值
4. `ok`：以上都不满足

定制任务汇总：如果现有 API 已经能拿到失败、排队中的任务数，直接复用，用于侧栏角标和待处理。如果拿不到，这两处先不显示定制相关信息，并在日志中注明。

  - 空库
