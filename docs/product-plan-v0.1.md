# 阿卷库存 v0.1 产品与技术计划

> 状态：首版方向已确认  
> 目标平台：Windows 10/11 x64、macOS Apple Silicon  
> 使用范围：个人、本地、单用户

## 1. 产品定位

阿卷库存是一款用于管理电动车发光小饰品成品库存的本地桌面应用。首版重点是清晰、顺手、可靠地完成商品建档、入库、出库、库存查询、流水查询和日期汇总。

首版不是通用 ERP，也不追求覆盖完整电商流程。产品以高完成度 UI 和可信的本地库存账为核心。

### 1.1 首版目标

- 在 Windows 和 macOS 上提供一致、成熟的桌面使用体验。
- 完成“商品 → 入库 → 出库 → 库存流水 → 汇总”的业务闭环。
- 数据完全保存在本机，无需用户登录或云服务。
- 支持历史流水和批量单据 CSV 导入。
- 支持数据备份与恢复，保证个人长期使用时的数据安全。

### 1.2 首版不包含

- 电商平台 API 对接
- 销售订单审核与物流履约
- 客户资料和客户隐私数据
- 原材料、生产、BOM 和加工流程
- 采购、供应商和完整财务模块
- 多用户、多组织、权限和审批
- 云同步与服务端
- 自动更新
- Windows ARM 和 Intel Mac 支持承诺

## 2. 已确认的业务范围

### 2.1 商品

- 首版只有一个成品，暂用名称“电动车发光小饰品”。
- 当前没有颜色、款式等规格选项。
- 底层仍采用“商品 SPU → SKU”两层模型。
- 无规格商品自动拥有一个默认 SKU，首版界面不展示规格编辑器。
- 商品包含编码、名称、单位、图片、默认进价、默认售价和库存预警值。
- 日常录单通过编码或名称快速选择商品。
- 数量只允许整数，金额展示保留两位小数。

### 2.2 入库

- 一张入库单可包含一个或多个明细行，数据模型不限制未来增加商品。
- 入库记录数量和实际进价。
- 支持备注和图片附件。
- 确认入库后增加库存，并更新移动加权平均成本。

### 2.3 出库

- 出库记录数量和实际售价。
- 可选记录销售渠道和外部订单号，不保存客户隐私。
- 默认销售渠道：抖音小店、淘宝、拼多多、微信、线下、其他。
- 销售渠道可以在设置中维护。
- 同一渠道下出现重复外部订单号时提示用户，避免重复扣减库存。
- 默认禁止负库存；库存不足时不能确认出库。

### 2.4 单据状态

```text
草稿 ──确认──> 已生效 ──作废──> 已作废
 │                │
 │ 可编辑、可删除  └─ 不允许直接修改或删除
 └─ 不影响库存        作废时生成反向流水并冲回库存
```

- 已生效单据可以查看、导出和作废。
- 已生效单据不能原地修改或删除。
- 草稿可以修改和删除。
- 作废记录和原始单据必须永久保留，确保库存账可追溯。

### 2.5 成本计算

库存采用移动加权平均成本：

```text
原库存：100 件 × ¥10
新入库： 50 件 × ¥13
新平均成本：(1000 + 650) ÷ 150 = ¥11
```

- 入库会重新计算平均成本。
- 出库按当前平均成本减少库存成本，不改变剩余商品的平均成本。
- 金额不使用浮点数保存。
- 对外金额使用整数分，内部平均成本使用更高精度的定点整数。

### 2.6 期初库存

- 首次使用时提供期初库存入口。
- 期初库存记录数量、单位成本和日期。
- 确认后生成不可删除的期初记录。
- 后续纠错通过受控的库存调整或反向记录完成，不直接篡改历史。

### 2.7 CSV 导入

首版支持两类用途：

- 历史库存流水导入
- 批量入库/出库单据导入

导入流程：

```text
选择 CSV
   ↓
解析字段与数据
   ↓
显示预览、预计库存变化和错误行
   ↓
全部通过校验？ ──否──> 不写入，提示修正
   │
   是
   ↓
用户确认
   ↓
单个数据库事务内完整写入
```

- 只要有一行错误，整批数据均不写入。
- 当前没有既有 CSV 样表，开发时先制定并提供标准模板。
- 字段映射兼容不在首版范围内；首版以标准模板为准。

### 2.8 数据备份

- 支持手动创建完整备份。
- 支持从备份恢复。
- 恢复前校验备份版本和完整性。
- 数据库和附件都必须包含在备份中。
- 应用数据保存在操作系统规范的用户数据目录中。

### 4.7 窗口与交互原则

- Windows 使用右上角最小化、最大化和关闭按钮。
- macOS 保留左上角交通灯位置。
- 内容布局在两个平台保持一致，不强行模拟另一平台的窗口外观。
- 首屏优先放置高频动作和库存结果，避免装饰挤占空间。
- 表格用于浏览和筛选；复杂编辑使用独立页面，简单编辑使用侧边抽屉。
- 所有可点击控件必须真实可用；未实现能力不显示或明确禁用。
- 必须覆盖空状态、加载状态、校验错误、保存成功、库存不足和危险操作确认。
- 首版视觉方案待低保真布局确认后单独决定。

## 5. 技术方案

### 5.1 技术栈

| 层级 | 选择 | 说明 |
| --- | --- | --- |
| 桌面容器 | Electron | 复用 `moyu-tools` 的双平台经验 |
| 构建工具 | electron-vite | 延续现有开发与打包经验 |
| UI | React + TypeScript | 适合表单、表格和多页面状态 |
| 样式 | CSS Modules + CSS Variables | 建立独立视觉系统，避免重型主题依赖 |
| 图标 | Lucide | 图标一致且已有使用经验 |
| 数据库 | SQLite | 本地单用户台账，无需服务端 |
| SQLite 驱动 | `node:sqlite`（Node 24 内置） | 仅在 Electron 主进程使用；Electron 43 与本机 Node 均自带，免原生模块重编译，测试与运行时共用同一实现。M1 实施时由 better-sqlite3 改为此方案 |
| 数据校验 | Zod | 共用表单、IPC 和 CSV 规则 |
| CSV | csv-parse | 解析、预览和错误定位 |
| 测试 | Vitest + 少量 Electron E2E | 重点覆盖库存账和关键操作流 |
| 打包 | electron-builder | 复用已有发布经验 |

首版不引入 ORM、Redux、插件系统、后端服务和重型 UI 框架。

### 5.2 进程边界

```text
┌──────────────── Renderer ────────────────┐
│ React 页面                              │
│ 概览 / 商品 / 库存 / 单据 / 汇总 / 设置 │
│ 表单状态、页面交互、展示格式             │
└──────────────────┬──────────────────────┘
                   │ 类型化、白名单 IPC
┌──────────────────▼──────────────────────┐
│ Preload                                 │
│ inventory.list()                        │
│ documents.create()                      │
│ csv.preview() / csv.commit()            │
│ backup.create() / backup.restore()      │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────▼──────────────────────┐
│ Electron Main                           │
│ 商品服务 / 单据服务 / 库存服务           │
│ CSV 导入 / 附件管理 / 备份恢复           │
│ SQLite 事务与 migration                 │
└─────────────────────────────────────────┘
```

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`
- renderer 不直接访问 Node.js、SQLite、文件系统或系统 API。
- preload 只暴露按业务命名的白名单方法，不暴露通用 IPC 方法。
- IPC 两端都校验输入，并验证消息来源。

### 5.3 初步数据实体

```text
products
└─ 商品基础资料

skus
└─ 默认 SKU；未来可扩展规格 SKU

documents
├─ 入库 / 出库 / 期初
├─ 草稿 / 已生效 / 已作废
└─ 渠道、外部订单号、备注

document_items
└─ SKU、数量、单价、成本快照

stock_movements
├─ 每次库存增减的不可变流水
├─ 变动前后数量
└─ 来源单据

sales_channels
└─ 可维护的销售渠道

attachments
└─ 单据附件的元数据和受控相对路径

schema_migrations
└─ 已执行的数据库版本
```

数据库的具体表结构在实现 M1 前单独设计并以测试验证，不在本计划中提前固化无用字段。

验收：用自动化测试覆盖入库、出库、库存不足、不同价格入库和作废，数量与成本均能对账。

### M6：UI 精修与双平台验收

- 确定最终视觉方向。

验收：核心业务闭环无需开发者工具即可完成；无假按钮、溢出、遮挡和不可恢复的危险操作。

## 7. 首版完成标准

满足以下条件时，v0.1 才视为完成：

1. 用户可以建立商品与期初库存。
2. 用户可以创建、确认和作废入库单、出库单。
3. 任意时点的库存数量和移动平均成本可以从流水对账。
4. 库存不足时无法确认出库。
5. 用户可以按日期、类型、渠道和单号查询记录。
6. 用户可以通过标准 CSV 批量导入历史流水和出入库数据。
7. 错误 CSV 不会产生部分写入。
8. 用户可以完整备份并恢复数据库与附件。
9. Windows x64 与 macOS Apple Silicon 安装包均可运行。
10. 核心 UI 覆盖空状态、成功、失败、危险确认和库存不足状态。
